# Skill: 修复测试失败（根因分析）

## 触发条件

mvn test 失败、测试报错、Tests run Failures、构建失败、断言失败

## 执行步骤（自动修复流程，最多重复 3 次）

### 第 1 步：解析 Maven 输出

从 `mvn test` 输出中精确提取：

- `Tests run: X, Failures: Y, Errors: Z` → 知道几个失败
- `<<< FAILURE!` 或 `<<< ERROR!` 后面的 `类名.方法名` → 哪个测试
- `java.lang.XxxException: 具体消息` → 什么异常
- `at 包名.类名.方法名(文件名.java:行号)` → 错误在哪个文件哪一行

### 第 2 步：分类错误类型

| 错误类型 | 特征                                            | 修复方式                                   |
| -------- | ----------------------------------------------- | ------------------------------------------ |
| 编译错误 | `cannot find symbol` / `package does not exist` | 检查 import、检查类名拼写、检查 Maven 依赖 |
| 断言失败 | `AssertionError` / `expected:<X> but was:<Y>`   | 检查业务逻辑是否正确，或断言期望值是否合理 |
| NPE      | `NullPointerException`                          | 检查未初始化的字段，测试中是否忘记设置值   |
| 类型转换 | `ClassCastException`                            | 检查返回值类型是否正确                     |
| 超时     | `test timed out`                                | 检查是否有死循环或网络调用                 |

### 第 3 步：定向读取

用 readFile 读取堆栈中指出的**具体文件和行号**附近的代码（前后各 10 行）

### 第 4 步：精准修复

用 editFile **只修改出错的那几行**，不要大面积重写

### 第 5 步：重新测试

executeShell("mvn test") → 如果仍然失败，回到第 1 步（最多 3 次）

## 关键规则

- **不要盲目修改**：必须先读堆栈、再读代码、再修复
- **不要输出"等待下一步指令"**：直接开始修复
- **3 次修复全部失败时**：输出具体的失败原因分析，让用户决策
