# Skill: 代码审查与性能优化

## 触发条件

用户要求代码审查、code review、性能优化、N+1 查询、慢查询、缓存、减少数据库调用

## 执行步骤

1. **精读目标代码**：
   - readFile 读取目标类/方法的完整代码
   - 标注代码行号，便于后续精准修改
2. **逐维度审查**：

### 维度 A：正确性

- 空指针风险（未检查 null）
- 并发安全（共享变量无同步）
- 资源泄漏（Stream / Connection 未关闭）
- 边界条件（空集合、空字符串、极值）

### 维度 B：性能

- N+1 查询（循环内查数据库）→ 改为批量查询
- 无分页的全表查询 → 加 Pageable / LIMIT
- 重复计算（循环内不变的值）→ 提到循环外
- 大对象序列化 → 考虑 @JsonIgnore / DTO 裁剪

### 维度 C：可维护性

- 方法过长（>50 行）→ 提取子方法
- 魔法值（硬编码的数字/字符串）→ 提取常量或枚举
- 重复代码（2+ 处相同逻辑）→ 提取公共方法
- 深层嵌套（>3 层 if/for）→ 提前 return / 卫语句

### 维度 D：安全

- SQL 注入（字符串拼接 SQL）→ 用参数化查询
- XSS（直接输出用户输入）→ 转义或白名单
- 敏感信息日志（log 中打印密码）→ 脱敏

3. **输出审查报告**：列出所有发现的问题 + 严重程度 + 建议修复方式
4. **执行修复**：用 editFile 逐个修复，每次修复一个小问题
5. **运行测试**：executeShell("mvn test") 确认修复不破坏功能

## 常见优化模式

| 问题                          | 修复                                      |
| ----------------------------- | ----------------------------------------- |
| 循环内 selectById             | 收集 ID 列表 → selectBatchIds 一次查      |
| 循环内 saveBatch              | 收集所有 Entity → 循环外 saveBatch 一次写 |
| `new ObjectMapper()` 在方法内 | 提取为 static final 字段                  |
| `String` 拼接在循环内         | 改用 `StringBuilder`                      |
| 全表 `selectList(null)`       | 加条件过滤或分页                          |

## 注意事项

- 审查报告中每个问题都要给出**具体的文件路径和行号**
- 性能优化要先确认是真正的瓶颈，不要过度优化
- 修复后必须跑测试验证
